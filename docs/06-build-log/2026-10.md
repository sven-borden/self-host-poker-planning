- **#1 (PP-001) merged, PR #61.**
  - The pnpm workspace has four packages: `apps/web`, `apps/server`,
    `packages/domain` and `packages/protocol`.
  - TypeScript 7.0.2 is strict, with project references (`tsc --build`),
    `moduleResolution: bundler` and `.ts` import extensions.
  - Tools: Biome 2.6.3; Vitest 5.0.5 with one project per package plus `scripts` and
    `db`; Vite 8.3.5; tsdown 0.23.2, which bundles the server and inlines `@pp/*`.
  - Node 24 is enforced twice: `engines` with `engineStrict`, and
    `scripts/check-node.mjs`. Both refusals were checked under a real Node 22 in Docker.
  - The review found that pnpm 11.1.2 has 17 advisories, so pnpm 12.15.0 is pinned.
    That version also makes `pnpm deploy` work for #11.
  - Other review fixes: `*.db.test.ts` stays out of the unit projects, `test:db` runs one
    file at a time, and the server starts with source maps.
  - There is no CI yet (#2) and nothing is deployed (#12), so the gate ran locally on
    fresh clones.
- Notes for later issues, from the review of #61:

  - #8: TypeScript 7 rejects `baseUrl` (TS5102). shadcn's `@/*` alias therefore goes

  - Windows: pnpm 12 writes `node_modules/.pnpm-task-run-state-v1/…` files. Keep a

- **#4 (PP-004) merged, PR #65.**
  - `packages/domain` gains:
    - the decks: five presets, the special cards, `deckCards`, `cardValue` and
      `cardLength`;
    - `validateCustomDeck`, with explicit codes including `card_invalid` and
      value-equal duplicates;
    - `generateRange`, which uses integer steps, so there is no float drift;
    - `computeResults`.
  - The reviewer ran the prototype's `stats()` against `computeResults` on 180k random
    rounds. The results match exactly, except the suggested card on exact midpoints. The
    PR breaks those ties toward the lower value; the prototype left them to float noise.
  - Review fixes:
    - Cards outside the deck sort by code point, so the vote order can never tie a value
      to a voter.
    - `Intl.Segmenter` is created lazily, with a code-point fallback for older browsers.
    - Range overflow returns an error code instead of an empty deck.
- Sven: two issues may run in parallel when they are independent, and one at a time
  otherwise. Each implementer gets its own worktree in `../pp-wt-NN`. #8 (web shell)
  started alongside #4; #3 starts now.
- **#3 (PP-003) merged, PR #66.**
  - The state machine is `apply(state, command, { actor, now })` in `packages/domain`,
    with 18 commands, `createRoom` and `DEFAULT_SETTINGS` (ADR-011). It returns
    `{ ok, state, causes, error?, ended? }`.
  - A refused command still returns the settled state, so a timer reveal is kept. An
    unchanged state comes back as the same object, so the server skips the write.
  - Rounds keep their own deck, specials and anonymity.
  - `startRound` works in every phase; during voting it abandons the round.
  - The automatic reveal is checked after every command, against the voters who are
    present. Deadlines fire exactly once.
  - 343 tests; the gate enforces 100 % branch coverage of `apply*`.
  - The review ran 2 million random fuzz steps against 15 invariants and found no
    violation.
  - Review fixes:
    - Names, titles and cards are capped in code units as well as characters.
    - Lone surrogates are refused.
    - Vote causes carry no `who` in anonymous rounds after the reveal.
    - `ended` returns the replaced round for the history writer.
    - Pruned votes emit `voteRetracted`.
    - Whitespace in names and titles collapses to single spaces.
- Notes for later issues, from the review of #66:
  - Presence (#17) must go through `apply` as a server-only command, so that a voter
    going away can complete a round. There is a TODO in architecture section 4.
  - History (#7, #33) is written from `ended` when `ended.phase` is `"revealed"`.
