# @pp/web

The browser app: a React 19 single-page app built by Vite, with TanStack Router
(file-based routes), Zustand, Tailwind v4, shadcn/ui and Motion. It renders what the
server sends and never decides the outcome of a round.

## Layout

- `src/routes/`: file-based routes (`__root.tsx` is the shell, `index.tsx` is `/`,
  `r/$code.tsx` is `/r/:code`). `src/routeTree.gen.ts` is generated by the router plugin
  on `dev`, `build` and `test`; it is committed (typecheck runs before build) and
  excluded from Biome. Never edit it by hand.
- `src/components/ui/`: shadcn/ui primitives, copied in and adapted (tokens, 44 px
  default targets, a 2 px brass focus ring, translated close labels).
  `src/components/shell/`: header pieces.
- `src/tokens.css`: the design tokens, the only place with colour literals.
  `src/styles.css`: Tailwind, the dark variant and the mapping of tokens to Tailwind and
  shadcn names.
- `src/theme/`: light, dark or system; `public/theme-init.js` applies the saved choice
  before first paint (external script: the CSP forbids inline scripts).
- `src/i18n/`: our own typed `t()` and the catalogs (#9); see "i18n" below.
- `src/motion/`: `AppMotionConfig` (reduced motion), `MotionFeatures` (lazy Motion
  features) and small wrappers.
- `src/table/`: the table (#13). `layout.ts` is the pure layout engine
  (`layoutTable(count, variant)` gives seat and slot centres as stage percentages, plus
  whole-pixel sizes; `GEOMETRY` holds the design brief's numbers), `geometry.ts` the
  pixel checks (stadium shape, clearances) shared by the unit test and Playwright.
  `TableStage`, `Seat`, `Avatar`, `HandCard`, `SlotCard` and `MiniCard` are
  presentational: props in, no store. `/dev/table` (`src/routes/dev/table.tsx`, lazy,
  noindex) shows them: `?n=1..16&state=lobby|voting|revealed&observers=0..4`.
- `src/stores/`: Zustand stores. `src/realtime/`: the typed Socket.IO client.
- `src/rooms/`: the room API (#14). `api.ts`: `createRoom({ name, deck })` (identity
  first, one session renewal on `unauthenticated`, a blank name left out) and
  `fetchRoomHeader(code)`; both reject with `RoomApiError` carrying the server's code or
  `network`; a `room_not_found` error carries the server's `retentionDays`.
  `create-room-card.tsx`: the self-contained "Create a room" card on `/`. It
  checks the name with the domain's `cleanRoomName` before sending, keeps the focus on
  the button through a failure (`aria-disabled`, never `disabled` while busy) and moves
  it to the name field when the name is refused. The room page (`routes/r/$code.tsx`)
  shows the header (name inside `<bdi>`, code, copy
  link with a toast, or the link to select when the clipboard is missing or refused) and
  a `[data-room-slot]` holding `RoomView` (below).
- `src/realtime/room-connection.ts` (#15): `openRoom(code)` follows one room (the room
  page calls it in an effect and returns its cleanup); `sendCommand({ type, payload? })`
  resolves with the ack. `src/stores/room-store.ts` holds `{ code, status, error,
  snapshot, connection }`; `status` is `connecting`, `live`, `reconnecting` or `error`
  (`error` holds an ack code, or `offline`). `removed` (#30) is set when the server said
  `kicked`: the server then closes the socket, and `openRoom` takes that close as a cue to
  connect again (not a final offline), so the page enters as someone not in the room and
  `RoomView` shows the join form under "The product owner removed you from this room."
  (`[data-room-removed]`, an alert) with the focus on the name; joining clears it.
  `receive` keeps only a newer
  version of the open room. A command belongs to the room open when it was sent: once
  that room closes, a send still waiting resolves `offline` and never reaches the next
  room. A command sent after an `await` takes `commandSender()` first: it binds to the
  room open at that moment, and resolves `offline` without sending if the page has moved
  on since.
- `src/room/` (#16): the room below its header, all from the room store.
  `room-view.tsx` (`RoomView`) shows `RoomStatus` (status line, participant count, the
  final errors and the reload prompt on `protocol_mismatch`), then, by the snapshot:
  - `you` is null: `JoinForm` (`join-form.tsx`: name prefilled from the identity store,
    checked with `cleanName`, then `join` through the `commandSender()` taken at the
    submit; voter by default), or the room-full screen when `isRoomFull(room)` or the
    server answered `room_full` at the current version. When observers do not count,
    `room_full` for a voter is an inline message instead (the observer row is still open).
  - `you` is set: `seated.tsx`, a lazy chunk prefetched when `RoomView` mounts: the table
    (`TableStage` with `tableData(room)`), the live region (`LiveAnnouncer`) and
    `YouControls` (`you-controls.tsx`: rename, voter/observer switch, leave), with the
    hand and the table's centre between them (#18, below).
  `save-name.ts` (`saveName`) saves the name for the next room before a join or rename:
  skipped when it is already the saved one (`/api/me/name` allows 10 a minute), and a
  failed save never stops the command, which carries the name typed. The copy lives
  under `seat.*` (the landing page's "Join with a code" card has `join.*`) and `you.*`.
  `table-data.ts` maps the snapshot to the table (#17): voters in join order, rotated so
  the viewer sits at the bottom, observers in the row. `seatStatus` gives `thinking` or
  `voted` while Voting (from `round.voted` only: no card exists before reveal), the card
  after a named reveal (`revealed`, which #19 flips); after an anonymous one `voted`, or
  `revealed` with no card for someone who did not vote (who voted is public);
  `personFlags` gives `away`, `owner`, `you` and the `look` from `avatarLooks` (table/
  avatar.tsx), computed over all participants in join order so every viewer sees the same
  initials and colours and no two people look alike. The first person in join order
  with each id colour (`avatarColour`) keeps it; only those who gave way are resolved
  after, so a rename changes no colour (up to 8 people) and a leave moves only people
  who gave way. Every seat is a popover button (`data-seat-trigger`, or the 44 px
  initials-only one) whose name is an sr-only span inside it; the popover says the whole
  name and what the badges mean. `isRoomFull` lives in
  `room-full.ts`, so the room route does not pull the table's code. The live region:
  `announcements.ts` turns a snapshot's causes into events (joins, leaves, away, back,
  first votes of others; never the viewer's own, never a card; since #30 removals, "The
  product owner removed Cleo from the room.", and the PO role handed over or claimed,
  said to everyone, the people it names too), merges a batch
  (repeats dropped, away-then-back cancelled) and words it ("Ana voted.", "3 people
  voted."); `live-announcer.tsx` follows every snapshot the store keeps
  (`useRoomStore.subscribe`, not renders) and speaks after 600 ms of quiet or 1.5 s at
  most, in `[data-table-live]`, a new element per announcement. Copy: `table.*` and
  `live.*`.
  Voting (#18): `hand-state.ts` is the hand's pure state machine. The snapshot's
  `yourVote` is the confirmed card; a press records a wish (a card, or null to take the
  vote back: pressing the card shown retracts), shown at once. One command is on the wire
  at a time; when its ack resolves, the store already holds its snapshot, so `nextStep`
  compares the latest wish with the confirmed card and sends again only if they differ
  (fast presses collapse; a wish the last command already carried is dropped rather than
  sent twice). A refusal, a `busy` that gave up or `offline` drops every wish: the hand
  rolls back and shows `failureMessage`. A wish belongs to its round (`roundKey`: number
  and start), so a new round or the reveal drops it; each command carries the round's
  number, and a `round_changed` refusal (the PO started the next round while it was on
  the wire) rolls back without a message. `use-vote.ts` runs the machine with the
  `commandSender()` taken at each press and words the viewer's own news ("Your vote: 5.",
  "Vote taken back.") for `[data-hand-live]`, a region nobody else gets: it compares the
  last accepted pick with `yourVote` in any phase, so the vote that ends the round is
  said too.
  `withShownVote(room, card)` folds the unconfirmed pick into the room the viewer sees,
  so their seat (face-down slot, voted badge), the centre's count and the hand agree at
  once. `handView(room, me)` (table-data.ts): no hand for observers, a line instead for a
  PO who does not vote (`poVotes`), else the round's `deckCards` (the room's own in the
  lobby), playable only while Voting; in the lobby and after the reveal the cards stay,
  `aria-disabled`, with the reason under them (#29 brings changes after the reveal).
  `table/hand.tsx` (`Hand`) is presentational: a toolbar with one tab stop (roving
  tabindex; arrows wrap, Home and End), `HandCard` toggle buttons (`aria-pressed`), a CSS
  deal-in on mount. `card-flight.tsx` flies a ghost card from the hand to the viewer's
  slot (`[data-slot-card][data-you]`, hidden through `TableStage`'s `hiddenSlot` until it
  lands) and back on a retract, with the Web Animations API (see "Motion" below);
  `flightKeyframes` is pure. `round-centre.tsx` (`RoundCentre`) fills the table's centre:
  "5/8 voted so far" while Voting (`voteCount`: voters, less a PO who does not vote, less
  people away who have not voted), in the lobby "Start voting" for the PO
  (`StartRound`, `[data-start-round]`) and "Waiting for the PO" for the others, and
  after a reveal the result (#20, below) and the recorded final estimate, the same for
  everyone. A voting round offers the PO no start: the domain would abandon it (PO
  default, #21). A refused start, reveal, final or re-vote shows under the table, above
  the results, and clears when the round or its phase changes. Copy: `round.*` and
  `hand.*`.

## Rules

- `pnpm dev` runs Vite on 5173 and proxies `/api` and `/socket.io` (WebSocket too) to
  the server on 3000.
- `pnpm build` writes static files to `dist/`; the server serves them in production with
  a history fallback, so `base` stays `/`.
- Every user-facing string exists in `en`, `fr` and `de` (see "i18n"). French uses
  vous, German uses Sie.
- No literal colour in `src/**/*.{ts,tsx,css}`: use token utilities (`bg-surface`,
  `text-ink-2`, `border-line`, `bg-primary`, …). `pnpm lint` runs
  `scripts/check-colours.ts`, which rejects hex values, colour functions (`rgb()`,
  `color-mix()`, … in any case), Tailwind palette classes and CSS named colours in
  arbitrary values, style objects and stylesheets. Only `tokens.css` is exempt.
  Tailwind's own palette is switched off in `styles.css`, so `bg-red-500` would generate
  nothing anyway, and Tailwind does not scan `scripts/` (its fixtures break the rule on
  purpose). A new token goes in `tokens.css` (both themes), in the `@theme inline` block
  of `styles.css` and in the design brief's table.
- Contrast: `--brass` and `--warn` are fills and accents, never text (use `--brass-ink`,
  `--warn-ink`); control borders use `--line-strong` (via shadcn's `border-input`), not
  `--line`.
- Motion: page entrances are CSS (`RiseIn`, tw-animate-css), so content never waits for
  JavaScript. Measured in #18: importing Motion's `m` (or `motion.tsx`) from a lazy chunk
  makes Vite 8's rolldown split shared modules (tailwind-merge, the English catalog,
  React's runtime) out of the entry chunk and costs the room route 12.8 kB gzipped. A
  keyframed one-off such as the card's flight or the reveal (#19) uses `Element.animate`
  instead (no dependency, interruptible with `cancel`, `matchMedia` for reduced motion;
  the reveal cost the lazy `seated` and `table-stage` chunks 1.8 kB and the room route
  nothing). Two splits
  keep Motion within budget, measured by #18's review: one lazy boundary for every
  Motion component (room route 167.6 kB), or a dynamic `import("motion/mini")` inside the
  effect (3.2 kB lazy). #20's results use `Element.animate` in their own lazy chunk
  (`results` 2.7 kB; the room route grew 0.3 kB with the English copy). #21's subject
  field and display add 2.0 kB to the lazy `seated` chunk (11.8 kB), the domain's
  `cleanSubject` and `linkKey` included: they sit in their own module
  (`apply-subject.ts`), apart from the join form's `cleanName`, so the room route grew
  only 0.2 kB with the English copy (168.1 kB) and the landing page 0.3 kB (152.0 kB);
  check the budget before reaching for `m` in a lazy chunk (ADR-008). An animated
  component wraps its `m.div` elements in `<MotionFeatures>`
  (`<MotionFeatures layout>` when it needs layout animations): the features chunk
  (`domAnimation`, or `domMax` for layout) is fetched when the first one mounts, never at
  page load. Biome refuses `import { motion } from "motion/react"`. Every animation has a
  reduced-motion variant (120 ms cross-fade, no travel).
- Budget: `pnpm build` ends with `scripts/check-budget.ts`, which reads the Vite manifest
  and fails when the initial JavaScript of the room route or of the landing page (entry,
  route chunk and their static imports) exceeds 200 kB gzipped. Lazy chunks (Motion features, the toaster, the
  French and German catalogs) do not count.
- Nothing connects at module load: `createSocket()` returns an unconnected socket.
  `connectWhenIdentified(socket)` connects it once `ensureIdentity({ retry: true })`
  resolved; on `connect_error` `unauthenticated` it runs the bootstrap once more and
  reconnects, and a second refusal sets the identity store's error, which the root layout
  shows as a toast (`errors.unauthenticated`). After `internal` or `rate_limited` it
  connects again with `retryDelay`'s backoff. The session cookie is httpOnly: never read
  it.
- Room sync rules: render the store, never decide. `openRoom` sends `enter` on every
  connect (a reconnect starts from a fresh snapshot); Socket.IO reconnects by itself, and
  only an `enter` refused with `internal`, `rate_limited` or `busy` is sent again with
  `retryDelay`. `sendCommand` waits for `live`, then sends with a fresh id; after a lost
  ack (disconnect) or `busy` it sends the same id again (at most 4 sends), which the
  server answers once; `{ ok: false, code: "offline" }` when the room never became live.
  When it resolves `ok`, the store already holds the new snapshot (the server
  broadcasts before it acks). Messages are checked by shape (`isSnapshot`, `isEnterAck`,
  `isCmdAck`), not with zod: zod costs the room route about 27 kB gzipped.
- The identity bootstrap holds the `pp-identity` Web Lock (two tabs, one guest), always
  takes the user from a session read, retries temporary failures (identity status
  `retrying`, a quiet toast) and stops at `cookies_blocked`. Render every user-provided
  name inside `<bdi>`.
- Browser code only: `tsconfig.app.json` covers `src/` with DOM types and no Node types;
  `tsconfig.node.json` covers `vite.config.ts` and `scripts/`, which run under Node 24's
  type stripping.
- `phone:` is a Tailwind variant for 640 px and below. The table does not use it: it
  measures the room its container gives it (`useRoomWidth()`) and picks its variant
  with `variantFor()`; inside the stage, style by `in-data-[variant=phone]:`. The two
  agree because the room page stays in the shell's column (`PHONE_MAX_ROOM` = 608 px of a

  on a small phone on its side.

## i18n

Our own typed `t()` on `Intl.PluralRules`, not i18next (ADR-012, amended in #9's
review: i18next and react-i18next cost 17 kB gzipped on the room route). The catalogs
keep i18next's JSON v4 syntax, so translation platforms read them and a switch back
stays cheap. The files in `src/i18n/`:

- `en.ts`: the reference catalog (`as const`), nested like `table.votedSoFar`; also the
  `Catalog` type that `fr.ts` and `de.ts` are declared with, so a missing or extra key
  fails `tsc`. English is bundled; `fr.ts` and `de.ts` are lazy chunks.
- `i18n.ts`: `t` and its types (`MessageKey`, `Params`, `TFunction`: template-literal
  types check each key and its placeholders), the current language (a module store with
  `subscribe` and `currentLanguage`), `changeLanguage`, `chooseLanguage` (also saves),
  `loadLanguage`, `startLanguage` and `fixedT(language)` for code outside React and tests.
- `language.ts`: `LANGUAGES`, `LANGUAGE_NAMES` (each in itself), `pickLanguage`,
  `detectLanguage` (the saved choice in `localStorage` `pp-language`, then
  `navigator.languages`, then English; storage errors are swallowed), and `localeFor`,
  the locale numbers and dates use (below). Tags split on `-` and `_`; `gsw` is German.
- `hooks.ts`: `useT()` (the typed `t`), `useLanguage()` (`[language, chooseLanguage]`)
  and `useFormat()` (the helpers below, bound to the current language and region). They
  re-render through React's `useSyncExternalStore`; there is no provider.
- `format.ts`: `formatNumber`, `formatDate`, `formatTime`, `formatRelativeTime`, each
  taking a locale; `Intl` formatters are cached on the locale and options, never values.
- `errors.ts`: `errorMessage(t, code)` turns a server error code into a sentence, with
  `errors.unknown` for a code this version does not know. Messages that state a limit
  (`bad_name`, `bad_seconds`, `deck_too_many_cards`, `card_too_long`) get it from the
  domain's constants through `ERROR_VALUES`, which `tsc` checks against the placeholders.

The region rule: numbers and dates use the first `navigator.languages` tag whose
language is the UI's (`de-CH` with German UI writes 6.5 and 1’234, `en-GB` a 24-hour
clock), else the bare language (`fr`, `de`: 5,5). Plural rules use the language.

Start-up and switching: `main.tsx` renders once `startLanguage()` and `router.load()`
have both settled, so the first paint is in the right language and a French or German
start costs no extra round trip. `startLanguage` gives up after 3 s and lets the page
render in English; the catalog still applies when it lands. Only the latest request
applies: `changeLanguage` keeps a pick counter, so a slow catalog never undoes a later
pick, and `chooseLanguage` saves only a pick that applied. `<html lang>` follows every
change. The switcher (`components/shell/language-switcher.tsx`) prefetches the other
catalogs when it opens, and shows the `language.loadFailed` toast when a pick cannot
load (offline, or an old chunk gone after a redeploy).

Adding copy:

1. Add the key to `en.ts`, then to `fr.ts` and `de.ts` (`tsc` reminds you). Call it as
   `t("section.key")` in a component that got `t` from `useT()`. Never write copy as JSX
   text or as a literal `aria-label`, `title`, `placeholder` or `alt`:
   `scripts/check-copy.ts` (in `pnpm lint`) fails on it.
2. Interpolate with `{{name}}`; `t("room.title", { code })` is type-checked against the
   placeholders. Values are inserted as plain text; React escapes them. Numbers use
   `{{count, number}}` (or `number(maximumFractionDigits: 1)`, options separated by `;`),
   never a bare `{{count}}`, so they follow the language and region. In code, use
   `useFormat().number` (or `formatNumber(value, localeFor(language))`); never
   `toString()` or `toFixed()` a number the UI shows.
3. Plurals: one key per form, `key_one` and `key_other` in English and German, plus
   `key_many` in French (`Intl.PluralRules` gives "many" from 1 000 000). Call
   `t("key", { count })`. `t` falls back to `_other` when a form is missing, but the
   catalog test requires every form, as i18next and translation platforms do.
4. Typography: ’ for apostrophes, never `'` or `"`, and … rather than `...`. French: a
   narrow no-break space (U+202F) before `:`, `;`, `!` and `?`, and « x » with U+202F
   inside. German: „x“.
5. A new server error code goes in `@pp/protocol`'s `ACK_ERROR_CODES` and in the
   `errors` section of all three catalogs; `en.ts` checks the codes with `satisfies`.

`src/i18n/i18n.test.ts` checks the catalogs at run time, so the checks hold even for a
catalog that skips the type check (a JSON import): the same keys in every language, the
plural forms each language's `Intl.PluralRules` needs and no others, the same
placeholders with the same formats, formatted number placeholders, no French or German
string equal to the English outside a short allowlist (`SAME_AS_ENGLISH`), the
typography rules, and a message for every code in `ACK_ERROR_CODES`. `t.test.ts` covers
`t` itself, the region rule, limits in error messages and slow or failing catalogs. The
French and German tone is reviewed in #41.

## CSP notes for #36

- `style-src 'self'`, no `'unsafe-inline'`: the app writes no `<style>` element. React's
  `style={…}` props go through the CSSOM and are not affected. Two libraries would write
  one, and are worked around: react-remove-scroll (under Radix Dialog, Sheet and
  DropdownMenu) through `react-style-singleton`, aliased in `vite.config.ts` to
  `src/csp/style-singleton.ts`, which adopts a constructed sheet; and sonner, whose
  `<style>` the `pp:sonner-styles-as-css` plugin cuts from the build (and fails the build
  if any is left), its `styles.css` bundled instead.

  element of their own (not through `react-style-singleton`). Whoever adds one must move
  that sheet into the app's CSS or a constructed sheet, and check it with
  `e2e/security.spec.ts`; the e2e guard fails any page that hits it.
- `script-src 'self'` is enough: there is no inline script. `public/theme-init.js` runs
  before first paint as an external file.
- `theme-init.js` has no content hash in its name, so it must be served with
  `Cache-Control: no-cache` (hashed files under `assets/` can be immutable).
